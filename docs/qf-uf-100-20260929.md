## Follow-up: `trans` fix + `cong`-over-`distinct` + resolution fast path

Subsequent fixes changed the picture substantially:

- `$last_eq_right` declared its premise tail `(eqs Bool)` — a fixed 2-element
  pattern — so `trans` failed on chains of ≥3 premises. Changed to
  `(eqs Bool :list)`; `trans` failures went from 85 first-failures to zero.
- `cong` could not reach `distinct` operands (packed in a single `eo::List`
  arg). New `$check_list_congruence` walks the two list spines elementwise,
  consuming premises positionally with optional reflexive entries — generic
  over any `eo::List`-argument operator.
- `resolution` dominated runtime (~93%) via a backtracking search with
  O(m²) set-compares per pivot on steps with up to 111 premises. Added
  `$check_chain_resolution`, a deterministic linear chain-resolve fast path
  falling back to the general search on any mismatch (sound: a chain success
  is inside the search's acceptance set). Case 030: ~200 s → 0.65 s.

## Timeout investigation and compact resolution accumulator

The subsequent fail-fast campaign initially stopped at
`qg5/gensys_icl1055.smt2`. In isolation it completed with `incomplete` in
56.4 seconds; resolution consumed 47.3 seconds (83.9%). Its two trusted
`THEORY_LEMMA` / `THEORY_UF` holes explain the incomplete verdict. It contains
16,555 resolution steps and 137,233 resolution premises. Detailed program
statistics confirmed that the deterministic chain path handled the steps;
the general search was not the source of the timeout.

Combining pivot membership with removal and using native clause concatenation
reduced this isolated run to 34.8 seconds. Both `gensys_icl1055` and
`gensys_icl636` subsequently finished in the ten-worker campaign. The next
timeout, `qg5/gensys_icl184.smt2`, exposed duplicate accumulation in the
intermediate resolvents: 12,256,128 recursive calls to
`$f_list_remove_every_elem` and about 3 GiB peak memory.

The final deterministic path represents each intermediate clause as a set:
deduplicate incoming clauses, remove their pivot, and add the remaining
literals without duplicates. The existing general resolution checker remains
the fallback when the chain does not match.

Isolated `ethos --stats` profile for `gensys_icl184` (15,663 resolution steps):

| Metric | Concatenated clauses | Final compact clauses |
| --- | ---: | ---: |
| Wall time | 67.15 s | 51.56 s |
| Resolution time | 60.34 s | 44.73 s |
| Expression construction calls | 47,945,523 | 17,862,075 |
| Resolution expression construction calls | 43,495,586 | 13,412,061 |
| Peak resident memory | 3,145,520 KiB | 610,432 KiB |
| Verdict | `incomplete` (two UF holes) | `incomplete` (same holes) |

The compact helpers explicitly distinguish the `false` nil terminator from
a clause operand `false`. Generic f-list membership visits the terminator,
so it cannot be used here to check false pivots or compare clause sets.
Dedicated operand membership and subset programs preserve that distinction.
Regression tests cover empty resolvents, duplicate literals, a real `false`
operand, a missing pivot, wrong polarity/conclusion/count, and a pivot
reintroduced by a later premise. An additional generated check with seed
20260929 passed 250 valid chains and 500 invalid applications.

Concurrent Ethos processes showed substantial slowdown on this environment.
Two copies of the compact proof each took about 120 seconds (roughly 119
seconds of user CPU time), compared with about 48 seconds for an earlier
isolated compact version. Ten and four simultaneous evaluator stages still
hit wall timeouts. These observations establish contention; they do not
identify its hardware cause.

The verification campaign therefore keeps ten pipeline workers for cvc5 and
Carcara, serializes Ethos, and uses a 180-second Ethos wall limit. Saved
certificates are reused for the final checker rerun, with every verdict
rechecked after the nil correction. Results are checkpointed after every
case. Artifacts: `/tmp/qfuf-100-failfast-20260929i/` and
`/tmp/ethos-resolution-final-20260929.log`.

The runner also exhibited intermittent subprocess stalls on small proofs.
`iso_icl1255` hit its 180-second campaign limit but passed direct checking in
2.21 seconds and a later replay of the same asynchronous command in 2.09
seconds. The small Goel `QF_UF_brp2.2.prop3_ab_reg_max` certificate also timed
out in the asynchronous runner. Capturing stdout/stderr to temporary files
and polling `Popen.poll()` instead of awaiting asyncio pipe completion made
the latter case complete immediately on replay. The remaining campaign uses
this process handling and `--stats` for per-case profiles. This observation
does not establish that every earlier timeout had the same cause.
